**On cosmos.gl alternatives** — what's not already in KG-EXPLORERS.md:

| Library | Why consider it | Why skip it |
|---|---|---|
| **Graphistry** (PyGraphistry) | GPU-accelerated, Python API, Jupyter-native, free tier, auto-clustering | Hosted (data leaves your machine), not single-file |
| **D3-force + Canvas** (custom) | Zero deps, maximum control, 10k nodes fine | You write everything — no built-in hover/select |
| **Cytoscape.js** | Mature, huge plugin ecosystem (cola layout, cytoscapeml), good for medium graphs | Canvas-based, slow past ~2k nodes, older API |
| **ngraph.pixi** | ngraph physics + PixiJS WebGL renderer, CDN-droppable | Two separate libs to wire together, sparse docs |
| **Observable Plot** | Tidy API for scatter/force charts, growing community | Not graph-native, no click-expand or focus mode |
| **Viva.js** | Simple WebGL force-directed, CDN-droppable, fast | Abandoned (last commit 2019), no active maintenance |

**Verdict**: cosmos.gl is still the best migration target for your use case. The only thing that would make me reconsider is if you need Python-side analytics tight-coupled to the viz — in which case Graphistry (they have a free tier) is worth a prototype.
